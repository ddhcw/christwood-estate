## Task
Work inside `projects/transport/` and `docs/rfcs/`. Every server function calls `gpsRequire_('manage')`; every save writes an audit row.
1. **Import (R30 job 1) — Q12 is OPEN: the school's stop sheet headers are unknown.** Build it header-agnostic: a `Stop_Import_Map` tab (code-owned, idempotent setup, editable data) mapping logical fields (stop_name, landmark, route_no, session, sequence, scheduled_time, admission_no, student stop) to the source sheet's real header names, with aliases. Source is a Sheet ID read from a setting (`stop_import_sheet_id`, blank = `TODO(human)`, never invent). Pure `parseStopImport(rows, map)` returns {stops, tripStops, studentStops, unmapped[]}. Idempotent upsert: stop identity = normalised stop_name; second run creates no duplicates; never overwrites a `verified_on`/coordinates already set; reports every unmappable row with a reason; imported stops get blank lat/lon, `coord_source` blank, `verified_on` blank (so engine skips them). Admission numbers normalise to `C0nnnnn`; invalid ones are reported, not written. A dry-run mode that writes nothing.
2. **Mark this stop (job 2)**: server fn takes stop_id + the bus phone's latest position (from Worker `/v1/latest` for the chosen vehicle, not from the client), rejects fixes older than 60 s or accuracy worse than 50 m, saves lat/lon to 6 d.p., `coord_source=driven`, `verified_by` = signed-in email, `verified_on` = today. A re-mark of a verified stop requires an explicit overwrite flag and logs old values.
3. **Map tap (job 3)**: server fn saving a tapped lat/lon with `coord_source=map_tap`, same verification fields, bounds-checked (within 30 km of the school row; reject 0,0 and out-of-range).
4. **Dwell suggestions (job 4)**: pure `suggestDwellStops(points, {minSec:20, radiusM:30})` over a track from `/v1/track`; output clusters (centroid, duration, count, time) not already within 30 m of an existing stop; suggestions are NOT written to Transport_Stops (only offered to be saved as `geocoded_draft`-style drafts via an explicit user action with `coord_source=map_tap`/`driven` semantics decided by the user's choice).
5. **UI** `GpsStops.html` + route `?page=gps-stops` (follow `GpsLive.html`/GpsEndpoints conventions): list of stops with a red "unverified" badge (icon + text), a big "Mark this stop" button, a map-tap picker, a dwell-suggestion list, dry-run import with the unmapped report. Honest state: show "Data as of HH:MM" for the position used.
6. Add `Stop_Import_Map` and any settings to GpsSetup.js without changing existing column order; update RFC-GPS-2 or the matching RFC briefly if access changes; add a PROJECT.md section.
